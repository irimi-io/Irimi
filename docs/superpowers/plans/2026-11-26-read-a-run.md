# Read a Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A recorded run can be listed, read as a tree, read back raw in pages, and shown by a bare `irimi` CLI.

**Architecture:** `StorageEngine` gains three reads that return plain data in opaque-cursor pages. Pure assembly functions turn events into reader documents, which are defined once in the store package. Starlette routes serve boundary 3 under `/api/v1/` and the replay read under `/v1/`. The CLI talks to the store over HTTP only and imports the document shapes.

**Tech Stack:** Python 3.12 (store, CLI), 3.10-compatible (SDK wire module), Starlette, uvicorn, SQLite, `argparse`, `urllib`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-26-read-a-run-design.md`. Read it and `CLAUDE.md` before any task.

## Global Constraints

- `CLAUDE.md` in full. In particular: no comments or docstrings in this work, full names, frozen dataclasses across module boundaries, `mypy --strict`, no `utils`/`helpers`, tests only through HTTP or the CLI, no network beyond localhost, no new dependencies.
- Before every commit all of these pass: `uv run ruff check`, `uv run ruff format --check`, `uv run mypy`, `uv run mypy --python-version 3.10 packages/sdk/src`, `uv run pytest`.
- Every route reads project `DEFAULT_PROJECT` (`"default"`).
- Storage calls from a route go through `run_in_threadpool`, as ingest does.
- Unknown fields and unknown event types are kept and returned. A reader never fails on an unknown kind, flag, condition or field.
- Times in every document are strings of nanoseconds. A core value the store lacks is `null`, never an absent key.
- Commit messages: imperative, what changed and why, ending with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Two PRs. Tasks 1 to 3 are PR 1, tasks 4 and 5 are PR 2. Each has its own issue and branch `<issue-number>-<slug>`, and its PR body says `Closes #<n>`.

## Review Focus

1. **Ids with URL characters.** A trace or span id is an opaque string and may hold a space, `#` or `?`. A reader expects the run to be readable: the CLI percent-encodes ids, the store decodes them. (Tasks 3 and 5)
2. **A bad `limit` or `cursor`.** `limit=0`, `limit=-1`, `limit=many`, a limit over the largest, or a cursor the engine did not issue is a 400 with a reason, never a 500. (Task 1)
3. **Parent links that loop.** A span that names itself as parent, or two that name each other, must not hang assembly. Both appear in `detached`. (Task 3)
4. **Untyped values of the wrong type.** `status` that is a number, `flags` that is not a list, `events_produced` that is a string. A status is shown as written, flags that are not a list count as no flags, no condition is derived from any of them, and the CLI prints what it gets with `str()`. Nothing answers 500. (Tasks 2, 3 and 5)
5. **The same span started twice.** A writer that retries with a new event id sends two starts for one span. The earliest to arrive makes the node and the other is listed in the node's `events`. (Task 3)
